# 製品概要

## 1. コンセプト

VLiveCameraUnit は、プロの現場水準を満たす直感的なライブ操作を核に、破綻しにくい追従、構図、補間、遷移を統合する Unity 完結型の次世代バーチャルライブカメラシステムである。

事前に多数のカメラとレーンを設計し、本番ではそれらを楽器のように選択・切り替える。カメラを選んだ時点で、ショット固有の動き、構図、レンズ、揺れ、遷移が意図どおりに開始される。オペレーターは必要に応じて距離、レーン速度、回転、ズーム、フォーカスなどへ重ねて介入する。

将来は候補提示やキュー支援まで段階的に拡張するが、Program を確定する最終判断は、少なくとも初期製品では人が持つ。

## 2. 到達像

本製品が目指す運用は次のとおり。

- 全ショットが、固定を含む明示的なレーンまたは運動規則を持つ。
- 切り替え操作だけでも、ライブ演出として完成した画が継続する。
- 「常に動く」は無目的な揺動を意味しない。静止、溜め、Hold も意図あるカメラワークとして扱う。
- 人の追加操作は自動挙動を壊す上書きではなく、予測可能なトリムや一時的な権限移譲として合成する。
- キーボードで全機能を開発・検証でき、MIDI は同じ操作モデルへ後から追加できる。
- 大量のショットを Bank、Preview、Tally、Multiview で迷わず扱える。
- AI は検証済みのカメラ文法に沿ったデータを量産し、実行時の安定性は共通 Runtime が保証する。

## 3. 製品原則

### 3.1 手動操作は「生の Transform 操作」ではない

手動操作の価値は、オペレーターがタイミング、ショット選択、強調量を即座に判断できることにある。追従計算、構図維持、補間、制限処理まで人へ負わせない。

### 3.2 切り替えだけで成立し、操作すると深化する

各ショットは呼び出しただけで意図ある Entry、Main、Exit または Hold を実行する。オペレーターが触れた場合は、動きの強さや構図をさらに演奏できる。

### 3.3 制御権はチャンネル単位で扱う

「常に手動優先」「常に自動優先」の一律規則にはしない。位置、注視、レンズ、フォーカス、ダッチ角、揺れなどの各チャンネルについて、パターン、支援、手動トリムの合成方法を定義する。

### 3.4 先に信頼できる手動基盤を作る

半自動化は、手動運用で実績のあるショット定義、状態、操作コマンド、履歴を利用する。初期段階で自律的な演出判断を Program へ直接反映しない。

### 3.5 AI はカメラワークのデータを生成する

AI にショットごとの専用 C# を生成させない。リグ、レーン、時間曲線、構図、レンズ、キャラクター性を表すデータアセットを生成し、Editor 検証と人のプレビューを通す。

## 4. 対象環境

- Unity 6.3 以上
- Cinemachine 3
- Unity Editor と Player の両方
- 初期入力はキーボードとマウス
- 将来入力は MIDI コントローラーを最優先候補とする

## 5. 初期スコープ

- Cinemachine 3 を用いたレーンベースのカメラリグ
- Program / Preview / Tally と Direct Cut / Take
- 論理上 64 台以上を扱える Camera Bank
- キーボードによるショット選択とライブ調整
- ショットごとの自律的なパターン再生
- 手動トリム、Hold、Resume、Reverse、速度・強度調整
- 低負荷 Multiview と Preview の事前準備
- 状態、入力、遷移、異常を確認できる運用 UI
- データ駆動のパターン作成・検証・プレビュー基盤

## 6. 初期スコープ外

- AI が本番中に Program を自動決定する完全自律ディレクター
- カメラワークごとに生成された個別 Runtime コード
- 特定 MIDI 機器を必須とする開発フロー
- Unity 外の専用送出ソフトを前提とする構成
- 実機カメラの物理制約を完全再現するシミュレーター

## 7. 成功の定義

成功は機能数だけでは判断しない。次を同時に満たすことを目標とする。

1. 初見のオペレーターがキーボードだけで安全に Preview と Take を行える。
2. ショット切り替えだけでもライブ映像として意図ある動きが成立する。
3. 経験者が複数パラメーターへ介入しても、不連続なジャンプや制御競合が起きない。
4. 多数のショットを登録しても、選択状態、Program、Preview、Tally を見失わない。
5. AI 生成パターンが共通検証を通り、コード追加なしでライブラリへ投入できる。
6. 実ステージ相当の長時間運用で、画、入力応答、メモリ、フレーム時間が許容範囲に収まる。
