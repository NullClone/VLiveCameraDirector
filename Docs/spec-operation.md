# 操作仕様

## 1. 目的

本仕様は、オペレーターがライブ中に行う操作、その意味、制御権、入力デバイスとの境界を定義する。初期開発と全機能の検証はキーボードとマウスで完結させ、MIDI は同じ操作コマンドを発行する Adapter として後から追加する。

## 2. 基本運用

標準ワークフローは次のとおり。

1. Bank を選び、候補ショットを一覧する。
2. Preview を選択して、構図と開始時の動きを確認する。
3. Take または Cut で Program へ送出する。
4. 呼び出されたパターンが自動的に再生される。
5. 必要な間だけ速度、距離、向き、レンズなどへ介入する。
6. 介入を解放すると、定義された復帰規則でパターンへ戻る。

Direct Cut モードでは、ショット選択を Preview 確認なしで Program へ反映できる。ただし通常運用は Preview / Take を基本とする。

## 3. 共通操作コマンド

物理キーや MIDI 番号は Input Mapping で変更可能にし、Runtime は次の意味コマンドだけを受け取る。

| コマンド | 種別 | 意味 |
| --- | --- | --- |
| `SelectCamera` | 離散 | 現在 Bank 内のショットを選択 |
| `SelectBank` | 離散 | 操作対象の Bank / Page を変更 |
| `Take` | 離散 | Preview を定義済み遷移で Program へ送出 |
| `Cut` | 離散 | Preview または指定ショットを即時に Program へ送出 |
| `RailDrive` | 連続 | レーン進行速度または進行量を操作 |
| `RailReverse` | 離散 | レーンの進行方向を反転 |
| `RailHold` | Gate | レーン進行を一時停止 |
| `Pan` / `Tilt` | 連続 | 注視・画角の水平 / 垂直トリム |
| `Zoom` | 連続 | 焦点距離または定義済みズーム量を操作 |
| `Focus` | 連続 | フォーカス距離またはターゲット基準オフセットを操作 |
| `Dutch` | 連続 | ロール角を操作 |
| `Height` | 連続 | リグまたは構図上の高さを操作 |
| `LateralOffset` | 連続 | 横方向の位置または構図オフセットを操作 |
| `MotionStrength` | 連続 | パターン全体の振幅・速度感を定義範囲で調整 |
| `ResetTrim` | 離散 | 選択チャンネルの手動トリムを既定値へ戻す |

コマンドには入力源、時刻、値、操作フェーズ、対象チャンネルを付与できる構造とする。入力デバイスのポーリング結果を直接カメラへ渡さない。

## 4. Camera Bank

- 論理上 64 台以上のショットを登録できる。
- 操作面は Bank / Page に分け、一度に認識する数を制限する。
- Bank 変更だけでは Program を切り替えない。
- Program と Preview は Bank を跨いでも識別できる。
- ショット番号だけでなく、短い名前、カテゴリ、主要ターゲット、状態を表示する。
- 未ロード、無効、使用不可のショットは選択可否と理由を視覚的に区別する。

登録上限、同時 Preview 数、Multiview 描画数は別設定とする。

## 5. キーボード初期操作

初期 Keymap はアセットとして提供し、次をキーボードだけで操作可能にする。

- 数字キーによる Bank 内ショット選択
- Bank の前後移動と直接選択
- Preview 選択、Take、Cut
- レーンの正転、逆転、Hold、Resume、速度調整
- Pan、Tilt、Zoom、Focus、Dutch、高さ、横オフセット
- Motion Strength と Trim Reset
- 操作対象チャンネルと入力値の確認

具体的な既定キーは実装時に Editor、Game View、OS ショートカットとの競合を確認して決める。キーの押下状態が UI フォーカス喪失後に残留しないことを必須とする。

## 6. 操作対象

初期版の連続操作対象は On Air、すなわち Program ショットを既定とする。Preview の選択・移動操作と Program の演技操作を混同させない。

将来 Preview ショットの事前調整を導入する場合は、明示的な Target モードと色・Tally 表示を追加し、無意識に Program 操作対象が切り替わらない設計とする。

## 7. チャンネル別の制御権

各チャンネルは次のいずれかの合成モードを持つ。

| モード | 動作 |
| --- | --- |
| Additive Trim | パターン値へ手動差分を加算 |
| Scale | パターンの速度・振幅を手動値で倍率調整 |
| Temporary Override | 操作中だけ手動値を採用し、解放後に復帰 |
| Latched Override | 明示的な Reset まで手動値を保持 |
| Gate | Hold / Resume のように進行可否だけを操作 |

チャンネルごとに復帰時間、復帰曲線、制限値を設定できる。操作開始・終了で位置、回転、レンズが不連続に飛ばないことを必須とする。

## 8. Pickup と値飛び防止

絶対値を出す MIDI フェーダーやノブには Soft Takeover / Pickup を使用する。デバイス値が現在の論理値へ許容幅内で到達するまで、その入力を適用しない。UI には Pickup 待ちの方向と到達状態を表示する。

相対エンコーダー、マウス、キーの増減入力は差分として扱う。接続、Bank 変更、ショット切り替え、Mapping 変更の直後に値が飛ばないことを検証する。

## 9. 応答と安全性

- Take、Cut、Hold は入力を受けたフレームで状態遷移を開始する。
- 連続操作は描画フレームごとに滑らかに反映し、入力平滑化による体感遅延を設定可能にする。
- 同一フレームで矛盾するコマンドを受けた場合の優先順位を決定的にする。
- 無効な対象への操作は Program を変更せず、理由を表示する。
- ウィンドウのフォーカス喪失、デバイス切断、例外時には Gate 入力を解除し、暴走を防ぐ。
- 緊急時に現在の Program を保持し、パターン進行だけを停止できる Master Hold を用意する。

## 10. MIDI 拡張契約

MIDI 対応では、ノート、CC、相対エンコーダー、LED フィードバックを Input Adapter と Output Feedback に閉じ込める。

- 特定製品名を Runtime のコアへ埋め込まない。
- Mapping Profile で Channel / Note / CC と操作コマンドを対応させる。
- Tally、選択、Pickup 待ちを対応機器の LED へ返せる。
- MIDI が未接続でも全機能が使用可能である。
- Hot Plug と再接続で Program 状態を変えない。

## 11. 受け入れ条件

1. キーボードだけで Bank 選択、Preview、Take、Cut、主要な連続操作を行える。
2. ショット切り替え直後からパターンが定義どおりに開始される。
3. 手動介入の開始・解放で目視可能なジャンプがない。
4. Program と Preview、現在の操作対象を常に識別できる。
5. 入力フォーカス喪失やデバイス切断で操作値が残留しない。
6. 後から MIDI Adapter を追加しても、カメラやスイッチャーの仕様を変更しない。
